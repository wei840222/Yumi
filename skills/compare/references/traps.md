# Comparison Traps

Patterns that weaken comparisons — detect early and recover.

## Research traps

- **Anchoring**: First option researched gets more depth. Consciously balance effort.
- **Availability bias**: Easy-to-find info weighted too heavily. Seek harder-to-find data too.
- **Confirmation research**: Seeking data to support the initial impression. Research both fairly.
- **Unequal effort**: 10 min on A, 2 min on B = invalid results. Track time or source count per option.

## Scoring traps

- **False precision**: 7.2 vs 7.3 is unhelpful noise. Use whole numbers.
- **Recency bias**: Latest data is not always best data. Consider trends and measurement conditions.
- **Halo effect**: One strong criterion inflates others. Score each criterion independently.
- **Constraint laundering**: Turning a hard must-have into a soft weighted score hides the real decision.

## Presentation traps

- **Burying caveats**: Confidence issues hidden at the end. Lead with uncertainty.
- **Missing weights**: Showing raw scores without weights misleads. Always show the math.
- **Ignoring context**: Same options, different user priorities = different weights.
- **Fake certainty**: Declaring a winner when research parity failed.

## Recovery

When one of these patterns appears:

1. Acknowledge it explicitly to the user
2. Re-research the affected dimension to parity
3. Rescore with balanced data
4. Note the correction in the output
